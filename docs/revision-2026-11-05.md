# Revisión y correcciones del 5 de noviembre de 2026

Se revisó la tienda de la rama main, partiendo del commit e43f6f9cfd6360fbb901f7b498d33c5765d7e7ec. Se conservaron la tienda, sus diez tablas y su configuración actual.

## Fallos corregidos

- **Contraseñas alteradas al autenticar:** registro y cambio de contraseña conservaban los espacios, pero login y comprobación de contraseña actual los eliminaban. Una contraseña válida con espacios exteriores impedía entrar o cambiarla. Ahora se valida sin modificar sus caracteres. La integración comprueba registro, login, cambio y rechazo de la variante recortada.
- **Fechas de oferta inexistentes:** Date.parse normalizaba días como el 30 de febrero y las 24:00, desplazando promociones sin avisar. Se comprueba la fecha normalizada contra los componentes originales y el límite inferior de MySQL. Los días bisiestos válidos siguen aceptándose.
- **Arranque y cierre sin coordinación:** API y Vite se iniciaban a la vez, sin comprobar disponibilidad; la salida inesperada de un servicio podía terminar con código de éxito. Ahora se comprueban puertos y API antes de iniciar Vite y se anuncia disponibilidad solo cuando funciona el proxy. El teclado lo controla el iniciador, que detiene ambos servicios con un límite de espera y código de error ante fallos.
- **Puertos inválidos:** se rechazan valores no numéricos, fraccionarios y fuera de rango. El backend conserva PORT=0 para asignación dinámica en pruebas; el iniciador necesita un puerto fijo y diferente del de Vite.

## Verificación real

Entorno Linux, Node.js 24, MySQL 8.0.46 temporal y Chromium. No se conectó al servidor MySQL del usuario ni se modificaron sus datos.

| Comando | Resultado |
| --- | --- |
| npm test | 7 pruebas aprobadas |
| npm run test:integration | 18 pruebas/subpruebas aprobadas con MySQL real |
| npm run test:ui | 5 pruebas/subpruebas aprobadas en Chromium |
| npm run build | Compilación aprobada |

Las integraciones incluyen autenticación, permisos, CSRF, catálogo, pedidos, reserva y devolución de inventario, ausencia de sobreventa, reintentos, privacidad y rechazo de esquemas ajenos. La nueva prueba del iniciador comprueba disponibilidad a través de Vite, SIGINT, liberación de ambos puertos y que un fallo MySQL no abra la interfaz ni anuncie éxito.

Las pruebas crean y eliminan bases temporales independientes. Windows y macOS requieren validación propia. Esta revisión no constituye una auditoría exhaustiva ni un despliegue de producción.
